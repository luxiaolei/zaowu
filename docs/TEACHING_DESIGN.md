# 教学设计：认识孩子之后，怎样教

## 1. 不是“完整档案 + 一次长提示词”

每次教学决策都回答：孩子现在想做什么？有什么相关经验？当前证据支持他独立做哪一步？哪里只是没观察过？下一种最小支架是什么？用什么可观察行为验证是否有效？

计划应包括目标作品、一个主要学习目标、当前证据、预备经验、孩子的真实决定、局部生成范围、提示阶梯、迁移任务、反思方式、预算、退出条件。

## 2. 统一项目循环

`Invite → Choose → Build → Test → Transfer → Reflect → Save`

Invite 用经历与兴趣邀请，不长篇讲解。Choose 由孩子做有后果的选择。Build 只做这一小步。Test 让孩子预测并观察。Transfer 换情境而非原题复述。Reflect 让孩子展示理由，无法表达时用选择/指认替代但标记证据局限。Save 保存作品和事件，不能把“点击保存”当成掌握。

## 3. 三个年龄段

| 年龄段 | 表达与支架 | 创作粒度 | 限制 |
|---|---|---|---|
| 5–6 | 家长读题、2–3 个具体选择、实物图示 | 每步一个变量；观察和指认 | 不要求独立阅读；误点/语言不明不评分 |
| 7–9 | 短句引导、先猜后试、解释一个理由 | 2–3 个相关决定，小变式 | 不用抽象术语遮住具体任务 |
| 10–12 | 更复杂约束、比较策略、迁移与反例 | 可以自行规划一小段并修改 | 不能默认同年龄都掌握同内容 |

这只是初始脚手架，不是年龄能力诊断。当前试用数量/规律任务已有年龄变式；故事表达深度、语音和更开放评价是后续任务。

## 4. 提示阶梯

H0：请孩子预测或自己试；H1：提醒相关目标；H2：把任务拆一步；H3：给不同题面的相似例子；H4：一起完成这一小步，随后给新变式验证。

每次提示写入 trace。帮助不是惩罚，提示次数不用于公开排名。成功后逐步减支架，不把“曾经需要帮助”变成永久弱项。连续困难可换低压力活动或结束，不逼迫为了完课一直猜。

当前实现：一次 authored hint + 自动提示，区分首次独立/支持后完成。完整 H0–H4、多种支架有效性比较尚未实现。

## 5. 错误如何解释

只记录“在某规则任务中选择了某项，未通过”，不立即断言认知原因。后续候选原因可包括：没理解题意、误触、策略错误、知识未稳、任务设计问题、识别不清；若没有证据，reason=unknown。

选择验证任务而非直接贴标签。例如“3 个包裹、每箱 2 个”，孩子回答 1：先让他拖拽分组，看是否能把多出的包裹单独放箱。看到第二种行为后才提出“余量需要另一个容器”的支架建议。

## 6. AI 不能代做的边界

孩子必须拥有至少三项实质决定，例如主角/目标、策略/规则、修改/评价。生成器只能对批准的局部执行 patch。不能看到请求“做一个游戏”就生成成品然后记作孩子完成。

评价不奖励 AI 写得更漂亮；记录孩子提出、验证、修改与迁移的行为。绘画好看不是数学掌握，语言流利不是理解充分，听完解释不是独立会做。

## 7. 课堂脚本例子（合成）

背景：喜欢海洋，做过积木，两次不同任务在分组比较中需要提示。

邀请：“上次你搭过运输工具。今天让小鲸鱼给海岛送物资，你想带食物还是种子？”
决定：“每个气球能带两个。先摆三个包裹，你觉得几只气球够？”
支架：“我们先把两个圈在一起，剩下的放哪儿？”
验证：“这次变成五个包裹。先自己试，完成后再告诉我你的办法。”
迁移：“改成每个小船能带三个，怎么办？”
反思：“你最想给家长看的是哪个决定？我们把它写在作品旁边。”

此脚本说明未来动态引导逻辑；并非当前试用的全部交互已实现。

## 8. 课程包发布流程

作者写目标/技能/题面/提示/变式/误判风险 → 用合成画像测试推荐 → 内容审查 → 真实设备可用性 → 少量家长陪同试用 → 收集非敏感结构化反馈 → 审核后发布版本。修改评价规则必须升 rubricVersion，不能静默把旧证据按新规则改写。

## 9. 验证是否真的个性化

至少比较：冷启动与回访、同兴趣不同历史、同历史不同支持偏好、一次误点与多任务困难、撤回前后、近期与过期证据。观察教学计划是否发生合理改变，而不是只插入孩子喜欢的动物名称。

指标是任务过程、迁移、再创作意愿与家长对解释的信任；先做定性观察和小规模可行性，不用未经校准的“提升 X%”营销。
