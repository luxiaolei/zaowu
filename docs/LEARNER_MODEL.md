# 学习者模型与长期记忆

这是系统核心，不是聊天日志的一个摘要提示词。

## 1. 六层模型

| 层 | 例子 | 来源与有效性 |
|---|---|---|
| 家长/孩子声明 | 喜欢海洋、做过积木、这次希望一步一步 | 明确来源与修改时间；不是永久人格 |
| 经历与作品 | 做过天空运输，修改两次，选了紫色 | 来自作品与事件事实 |
| 观察证据 | 在任务 X 中首次未通过；提示后完成 | 有任务、版本、情境、是否提示、时间 |
| 技能状态假设 | 分组比较还需要支架；迁移证据不足 | 可重算、可撤回、有置信度与反证 |
| 支持效果 | 分组图示之后恢复独立尝试 | 区分相关与因果；不是“视觉型学习者” |
| 目标与计划 | 下次先分组，再换成救援任务 | 教学策略产物，不反过来当能力证据 |

不记录敏感儿童履历、心理诊断、智力标签或家庭关系推断。兴趣不等于能力；阅读慢不自动等于理解弱；语音识别失败不等于孩子答错。

## 2. 数据不能混成一段文本

`LearnerProfile` 管理授权声明；`ProjectHistory` 管理经历；`EvidenceEvent` 是观察事实；`SkillEstimate` 是规则/模型推断；`MemoryClaim` 是有来源可纠正的自然语言记忆；`TeachingPlan` 描述下一步。

当前试用只实现 profile/project/evidence/派生技能/recommendation，**没有向量数据库和 LLM 自动记忆提取**。正式版先用关系查询，再考虑向量检索；向量只是派生索引，不是真相来源。

## 3. 证据结构

```json
{
  "id": "synthetic-project:main:1",
  "childId": "synthetic-child",
  "projectId": "synthetic-project",
  "taskId": "main",
  "skillId": "comparison",
  "contentKey": "comparison:5:2",
  "context": "delivery",
  "attempt": 1,
  "hintUsed": false,
  "outcome": "retry",
  "at": "2026-11-11T00:00:00Z",
  "rubricVersion": "local-rubric/1"
}
```

`outcome`: independent（首次无提示成功）、supported（提示后或重试后成功）、retry（未通过本次规则）、observation（非评分行为）、uncertain（无法判定）。不要把 observation 强行加为能力分。

同一个任务的连续猜测只有一个首次机会；相同内容重复刷不能积累“多情境掌握”。支持后正确不覆盖之前事实，但也不能永久把孩子锁在低难度。

## 4. 当前可执行启发式

代码：`site/src/memory.js`，版本 `local-rubric/1`。

- 无可评分证据 → `unknown`。
- 有少量任务 → `exploring`。
- 至少两种不同题面在首次机会未通过 → `support`，只表示下次提供支架。
- 至少三种不同题面首次无提示完成且跨两种情境 → `progress`，不用“精确掌握”措辞。
- 超过 30 天没有新证据 → `revisit`，不自动降低能力分。
- 超过 90 天证据不进入推荐；下次保存执行清理。

这些阈值是**产品启发式、待验证**，不是教育研究结论。样本量、任务质量、内容相关性会影响可靠性。近期错误和进步的衰减/权重还需在 v0.2 校准；不把当前累积规则当成已完成的知识追踪模型。

## 5. 教学决策如何消费模型

课前：只取当前作品相关的 1–3 个技能、最近 2–3 项经历、明确兴趣/支持偏好。构造版本化 `TeachingContext`，不得把全量聊天倾倒进 LLM。

课中：每次真实操作写入证据；LLM 生成的是“建议如何说”，不是授权自己改掌握值。发现多次卡住先检查题目/语言/交互和疲劳，不直接加难或负面评价。对无法判定的回答写 uncertain 并给低压力验证任务。

课后：作品实际完成情况、孩子做出的决定、独立/支持后的表现分开汇总。新结论列出来源，家长可否定；下一任务要给孩子拒绝和换主题的权利。

## 6. 个性化例子（合成）

A 和 B 都喜欢海洋、年龄同为 7–9。A 在不同任务的分组比较需要提示，B 已在不同情境独立完成。下一次两人都做海底救援：A 先把物资两两分组，B 先预测物资增加后需要多少运输工具。不是只把题干里的“汽车”换成“鲸鱼”。

家长说 A 那次是误触：撤回该证据 → 重新聚合 → 若支持阈值不再满足，推荐不再引用该次失误。线上应使向量索引、摘要缓存、教学计划快照失效并保留最小审计标记。

## 7. 记忆提取的后续安全边界

LLM 只能提出候选 `MemoryClaim`，字段含 source_event_ids、kind、confidence、expires_at、visibility、approval_state。声明必须引用真实来源；未经证据支持的心理/健康/家庭推断直接拒绝。外部内容、孩子话语、作品文字都是不可信数据，不能作为系统指令。

冲突不“最后一条覆盖一切”：偏好可以随时间变化；某次表现和长期趋势可以并存；家长更正优先限制使用，但不得伪造成功证据。

## 8. 删除与隔离

服务端从认证会话解析 family_id，再校验 child_id 所属。缓存键、向量命名空间、对象路径、job payload 都包含 tenant/child，且访问不能只信前端。

删除一条证据：移除/撤回原记录 → 重算聚合 → 删除相关派生记忆和检索项 → 失效缓存 → 取消还未执行的计划。
删除孩子：停新任务 → 删除热数据/资产/索引/队列 → 供应商删除请求 → 记录备份到期与处理状态 → 给家长回执。不能承诺立即擦除已不可逆训练的数据，因此默认退出供应商训练是准入要求。

## 9. 验收

必须覆盖不同孩子不串记忆、重复事件幂等、同一题不刷掌握、一次错误不贴标签、提示后正确不冒充独立、uncertain 不评分、过期不引用、删除后不复活、家长纠正影响下一计划。相应单元测试已经放入仓库；真实儿童教学有效性验证仍待完成。
