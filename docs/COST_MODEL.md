# 成本与预算设计

## 0. 先纠正口径

当前静态试用不调用任何付费 AI API，模型成本为零；这不等于正式产品零成本。托管、域名、内容制作、研发和支持需要另计。此前讨论中的供应商分钟单价、汇率、语音费率并不是本仓库确认过的现行报价。

`tools/cost.mjs` 的默认数字全部是**可替换规划假设**，没有承诺 ¥129 就能盈利。

## 1. 成本拆分

每个家庭/项目成本 = LLM 输入输出 token + 检索/记忆更新 + ASR 分钟 + TTS 字符/秒 + Avatar 实际计费分钟 + 生图/编辑/审核/重试 + 存储/带宽 + 安全审核 + 支持分摊。

套餐平均单价还要除以实际利用率。未使用额度不能当成零成本；并发容量、最低计费、闲置时间、失败账单、税费与企业阶梯需要单独核查。

净收入 = 订阅实收 − 退款 − 支付/渠道费 − 税费（依适用口径）。贡献 = 净收入 − 可变成本。获客按实际留存分摊；再减固定研发/运营才能谈利润。

## 2. 可运行计算器

```bash
npm run cost
LIVE_MINUTES=0 PRICE_RMB=99 IMAGE_CALLS=12 npm run cost
LIVE_MINUTES=24 IMAGE_RMB=0.5 PLAN_UTILIZATION=0.7 npm run cost
```

默认假设：12 次 × 20 分钟/月，8 分钟 Avatar、0.26 USD/min、假设汇率 7、套餐利用率 80%；24 次图片调用，每次 ¥0.25，失败/重试系数 1.15；LLM ¥12、语音 ¥8、存储审核 ¥5；售价 ¥129，费用3%、退款5%；CAC ¥100、假设4个月分摊。

默认图片单价不是任何厂商报价；默认 LLM/语音成本也不是实测。计算器是情景分析，不是会计模型；税费、固定成本、每笔手续费等需另加。

## 3. 预算成为系统能力

每家每月预算、每项目预算、每请求上限三层限制。付费请求执行 `reserve → execute → settle/reconcile`；重复 key 不重复扣款，取消不意味着供应商已退款。账单未知标记 pending，不盲目自动重试。

模型选择依质量/安全/预算门控，不用“全部请求最贵模型”。周期摘要按作品事件批处理，不能每一字都重写孩子记忆。读取局部教学上下文，不把全部经历塞进 prompt。

## 4. 图片的经济模型

图片不能无限刷。普通背景用已审核素材；个性化生成只围绕孩子的关键决定。每个项目先给有限候选和局部修改次数，超额仍可用本地插画完成作品。

不要把失败图片、审核拒绝、参考图上传、编辑调用、高清放大、CDN 与保存长期成本漏掉。审核不过可以算供应商费用，但不能记作孩子完成了一张作品。

## 5. Avatar 成本

全程实时视频不是默认方案。提供 Canvas/Voice/Live 三种模式；Live 按价值窗口创建，显式关闭并确认终态。媒体已停但 session 仍 active 时要告警。并发按高峰到达率 × 平均会话占用估算并留安全余量，不用月均分钟推出可承受并发。

## 6. 实验门槛

先测每个有效作品实际成本、p50/p95 与极端家庭；再测个性化/生图/实时角色带来的完成与回访增量。若增量价值不足，保持低成本形式，不为了供应商功能而牺牲单位经济。

盈利判断需要实收、留存、CAC、支持工时、退款、渠道费用和全量失败成本；本地试用无法证明这些。
