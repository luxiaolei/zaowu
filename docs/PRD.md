# 产品需求文档（PRD）

版本 0.1.0；负责人：项目维护者；状态：已确认方向 / 部分可运行。所有验收条件均应能在测试或试用中观察，不用“懂孩子”“有温度”代替验收。

## 1. 用户问题与目标

孩子不是零历史的匿名问题输入者。他有做过的事情、兴趣、擅长的表达方式、还不稳定的知识和过去有效/无效的支架。系统应据此确定下一件作品、难度、讲法、干预时机和复习任务。

目标是增加**孩子自主决策后的有效作品完成与再创作**，而非自动生成量、在线时长或被动观看量。

非目标：考试承诺、心理/智力测评、开放社交、无限陪聊、全程真人数字人视频、无审查开放代码执行、替家长作诊断。

## 2. 用户角色

| 角色 | 需要 | 权限 |
|---|---|---|
| 孩子 | 立即看见可以做的事、有限选择、及时反馈、可改作品 | 在受管空间创作，不管理支付或隐私授权 |
| 家长 | 知道孩子做了什么，为什么推荐，能纠正记忆 | 创建/管理档案、授权、删改、下载、批准分享 |
| 内容设计者 | 课程包、技能映射、支架和评价样例 | 只使用合成/去标识化样例，不访问全部家庭数据 |
| 维护者 | 安全运行、观测质量与成本 | 最小权限，不默认看儿童对话正文 |

## 3. 信息架构

孩子：创作岛 → 项目工作室 → 插画工坊 → 我的作品。
家长：孩子设置 → 作品过程 → 学习备忘 → 推荐依据 → 记忆纠正/数据管理 → 授权与预算。
后台未来：课程包版本、技能图谱、审核队列、模型路由、用量账本、删除任务。

## 4. 关键用户旅程

### 首次开启

家长声明陪同并选择最少信息 → 孩子从三个项目挑一个 → 选主角 → 选配色 → 局部任务 → 换情境验证 → 回顾选择 → 私密保存。

验收：不输入姓名、学校、生日；不需要模型密钥；不能跳过全部创作决定直接完成；无需拍照/开麦。

### 回访

读取当前孩子范围内有效证据 → 明确“上次做了什么” → 给下一任务及原因 → 可以拒绝推荐/换主题 → 根据支架需求调整提示 → 新证据修正旧结论。

验收：两名兴趣相同但任务历史不同的孩子，教学支持可以不同；删除历史后不能继续引用它。

### 家长纠正

打开某条判断 → 查看源项目、任务、首次/重试/提示情况 → 标记“不作依据” → 派生技能摘要与下一建议即时更新。

验收：没有只删除聊天而保留向量副本的“假删除”；正式服务删除派生索引和缓存。

### 生图共创（后续）

孩子先决定用途、主体、场景、配色 → 编译安全提示词 → 预算预占 → 生成 1–2 个候选 → 审核通过才显示 → 孩子指出要改哪一点 → 局部修改 → 保存到作品，不以 AI 代做全项目。

## 6. 课程设计要求

每个项目包必须声明：适用经验范围、前置技能、目标技能、可观察行为、三项以上创作决定、最小种子作品、渐进提示、迁移变式、不能据此推断什么、家长解释、成本上限、无网络降级。

先建立小而可靠的技能图，不声称覆盖整个小学课程。当前五类技能为创作机制试验，不是国家课程标准或能力测评。

## 7. 非功能要求

试用：零第三方运行依赖、无 API Key、无采集设备权限、单浏览器数据隔离键、键盘可操作、移动端无横向溢出、错误不阻断回到首页。

联网版目标（待压测）：首个界面可操作 p95 ≤ 3 秒；文字反馈首响应 p95 ≤ 2 秒；生成任务异步可取消；平台不可用时作品仍可读写；每个 provider timeout/retry 有硬上限。以上是设计目标，不是当前实测服务 SLA。

安全：不允许凭客户端 child_id 访问其他家庭；不给 LLM 任意数据库/HTTP/shell 工具；所有生成 patch 由程序校验；日志默认无原始儿童内容。

## 8. 产品指标

北极星候选：每周完成至少一个“包含孩子真实决定、一次尝试/修正及可展示作品”的家庭比例。

辅助：首次项目完成率、主动二次创作、D7/D28 回访、迁移任务表现、家长对推荐合理性的评价、撤回观察比例、支架后是否恢复独立尝试、每个有效作品的真实成本。

不要把更多提示/更长聊天解释为学得更好。实验比较同任务、同预算的固定引导与个性化引导；记录年龄/经验差异，报告不确定性，不拿小样本宣称因果效果。

## 9. 发布门槛

v0.1.0：功能闭环与隐私标示可见，单元/E2E 通过，仓库不含真实儿童资料。
v0.2：账号隔离、监护授权、数据流清单、供应商书面适用资格、输入输出安全、预算熔断、删除演练、有限家庭陪同测试。
v1.0：稳定的内容质量/学习体验证据、支持流程、可接受真实单位经济、真实浏览器/设备覆盖，不用单次演示代替。
