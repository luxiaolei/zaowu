# 实现路线与发布门槛

以验收而不是承诺日期推进。阶段可并行的只有互不改变公共契约的工作；认证、证据模型、安全与成本门控是共同前置。

## M0 · 本地引导试用（本次交付）

已有：公开仓库、中文文档、静态 Web、家长入口、三个有限项目、年龄/兴趣/经验设置、结构化证据、历史推荐、家长纠正/删除/导出、程序插画、单元测试、CI 与 Pages。

不是：成熟 AI 产品、云端家庭账户、自由对话、真生图、实时数字人、正式儿童数据合规服务。

验收：无密钥可运行；孩子能有意义地完成活动并保存；回访/撤回会改变推荐；界面不把预置规则冒充大模型。

## M1 · 可靠的个性化核心

依赖 M0 观察。实现家庭认证、多孩子隔离、数据库迁移、同意记录、事件幂等、证据版本、逐条纠正与派生删除、Context Builder 与服务端教学计划。

先完善 10–15 个经过内容审查的项目变式，而非扩大到几百个低质量模板。增加不确定回答、误触、语言困难的区分流程；完整 H0–H4 支架与逐步撤回。

门槛：跨租户负面测试全过；删除演练可验证；两个相同兴趣但不同证据画像产生合理不同计划；过期/撤回证据不再被引用。

## M2 · 真正 AI 引导与生图

并行轨 A：接 DeepTutor 或其他 LLM 的受限适配器；先只负责一轮提问/反馈，不允许直接生成整件成品或任意操作工具。

并行轨 B：ImageProvider + 结构化创意 brief + 安全审核 + 预算预占/结算 + 任务取消 + 私有素材库；先不收儿童照片。

并行轨 C：结构化画布/SceneGraph，受限 patch、版本 diff/回滚、作品隔离预览。

共同门槛：供应商地区/年龄/数据训练条款核查、服务端 Key、安全输入输出检查、预算熔断、故障降级。未通过不向真实儿童开放。

## M3 · 语音与有限实时角色

先做合规语音与本地轻量角色。验证它们是否改善创作而非增加聊天。Vivix/同类作为可选表现层，只在明确价值窗口启用，不是核心依赖。

门槛：实际设备上的延迟、打断与会话关闭对账；家长单独授权；超时、退出、断连、额度耗尽均能回到画布；没有“视频没播却一直计费”。

## M4 · 家庭试点与商业验证

家长陪同、明确有限范围与反馈机制。逐步收集同意的最少评估数据，比较固定引导和个性化引导。关注作品完成、独立决定、迁移与回访，不用未经验证的能力分做宣传。

只有真实成本、留存、家长付费与安全支持成立后，再决定收费、原生 App、更多作品类型。先做 Web，不把 iOS/Android 两套客户端当成学习效果问题的解决方案。

## 建议开发分工

| 领域 | 拥有的契约 | 可独立工作 |
|---|---|---|
| 学习者模型 | Evidence / Claim / Estimate | 证据聚合、纠正、过期与评估 |
| 教学与内容 | TeachingPlan / ProjectPack | 项目包、支架、迁移与误判审查 |
| 创作前端 | ProjectAction / SceneGraph | 画布、交互、私密作品展示 |
| 身份与隐私 | Family/Child scope / Consent | 认证、授权、删除、审计 |
| 媒体与费用 | ImageJob / AvatarSession / Ledger | provider 适配、预算、取消与对账 |

每个 PR 带测试与状态矩阵更新，不得把“设计了接口”标成“已接入”。
