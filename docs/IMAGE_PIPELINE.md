# 生图与视觉共创

## 产品价值

孩子的想法可以从一句描述、几个选择或草图，变成作品素材；重要的是孩子如何决定、评价和修改，而不是无限刷漂亮图。角色卡、故事场景、发明外观、网页插画、贴纸、作品封面都可使用同一资产系统。

## 当前实现

`site/src/art.js` 生成原创程序化 SVG。可选择三种场景、三个主体、三套配色并改变小细节；本地保存/下载。界面明确标注“本地矢量拼装，非 AI 生图”。不使用真实孩子照片，不调用外部模型。

## 目标链路

1. **孩子先决定**：用途、主体、场景、配色、要表达的特点；每轮聚焦一个改变，不要逼低龄孩子写长 prompt。
2. **创意摘要**：小芽复述已选内容，孩子确认；提取的个人信息先移除。
3. **输入门控**：年龄/地区/授权、适当内容、角色 IP/肖像、文件类型/尺寸/恶意载荷。
4. **预算门控**：家庭月预算、项目预算、剩余重试；原子预占，不靠客户端显示的余额。
5. **提示词编译**：将结构化 brief 转成 provider prompt；学习画像不直接进入提示词，只带必要创作偏好。
6. **生成**：默认一张，可选最多两候选；异步 job，幂等键、超时和至多一次可计费重试（可配置）。
7. **输出门控**：审核后才能显示；失败/不确定结果进入安全替代或人工审查，不显示原图。
8. **孩子评图**：“哪里符合你的想法？这次只改哪里？”支持局部编辑，不能每次重做整个作品。
9. **归档**：保存 asset_id、brief、来源、模型版本、授权、成本、审核结果、引用的作品版本。

## 数据结构

`ImageBrief`：subject、setting、palette、style、purpose、child_decision_ids、change_request。
`ImageJob`：family_id、child_id、project_id、request_id、status、budget_reservation_id、provider_id、model_version、created_at。
`AssetRecord`：private_object_key、hash、moderation_status、rights_status、generated_by、prompt_version、approved_for_display、cost_actual。

不把公开 URL 当资产权限。签名 URL 应短时有效，下载需授权；不要让供应商拿到整份孩子档案。

## 状态机

`draft → approved_brief → reserved → submitted → generated → moderated → selected → attached`
失败分支：blocked / budget_denied / timed_out / moderation_failed / cancelled。

cancelled 的迟到结果不得自动回贴；预算只结算一次；实际费用未知时标记 pending_reconciliation，不假装零成本。审核失败不是用户“再试一下”就可绕过。

## 成本策略

优先使用已审查素材库 + 局部拼装；课前可预生成非个性化背景；同一家庭同 brief 可重用缓存；跨家庭缓存只能复用无个人信息且有可复用权利的公共素材，不混用儿童上传图片。

设项目 2–4 次生成软上限、家庭月配额（待试验）；新候选必须回答一个具体创作问题。超额回到本地拼装，而不是阻止孩子保存已有作品。图像压缩/尺寸限制、编辑而非重生成、出图质量缓存是成本工具，但不能绕过安全审核。

## 儿童安全和版权

默认关闭真人照片、面部/声纹上传和逼真人物换脸；使用原创非真人角色。不生成色情、惊悚血腥、危险模仿或羞辱内容。提示词不能让 LLM 自己决定合规放行。任何上传/生成供应商须另外核查儿童数据、地区、训练用途、保留/删除和分包方。

## MVP 接入顺序

P0：已实现本地素材与场景组合。
P1：服务端可插拔 ImageProvider、预算预占、输入输出审核、1 张出图、无儿童照片、家长陪同。
P2：角色参考图一致性、多画面故事、局部编辑、版本对比、家长批准私密分享。
P3：视频/实时世界不是前置依赖；先证明生图确实帮助表达和完成作品。

## 验收

孩子三项决定反映到 brief；画像/原始语音不泄露；审核前没有图片可见；重复请求只计一次；取消不会迟到覆盖；预算失败有本地降级；删除孩子删除资产和派生缩略图；未经授权不公开作品。
